# Local document restoration status
The public site now includes the actual local library directory whenever validated files have been committed, and checks every declared file's SHA-256 before deployment. New resource IDs absent from the original 17 November baseline require a local manifest match in the explicit Pages workflow. Existing external-only records remain in the recovery register instead of being removed. The separately configured branch-based Pages deployment may bypass the explicit validation workflow; branch protection / deployment-source configuration would be needed to enforce this universally.

Full source recoverability workflow fetches the current catalogue's actual links, checks public HTTPS redirects, file signatures and PDF rendering of first/middle/last pages, then records technical candidates and errors. It does not automatically mirror documents that lack evidence of permission. Blank forms, manual currentness, statutory consolidation and alternative editions still need review. Office candidates need conversion and visual review. The user requested permanent local hosting; recovery audit success is not equivalent to having published the file.
